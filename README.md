# 검단신도시 부자부동산 웹 프로젝트

검단신도시 부자부동산 홈페이지와 관리자 화면입니다. 기존 랜딩페이지의 네이비·골드 디자인과 매물/후기 관리 구성을 참고했지만, 브라우저 임시 저장 및 가상 매물·후기는 사용하지 않습니다. 매물, 고객 접수, 게시물, 이미지 파일은 Supabase에 저장하도록 구성했습니다.

## 로컬 실행 및 빌드

- Node.js 18 이상에서 `npm run build`로 `dist/`를 생성합니다.
- 개발 서버: `npm run dev`
- 이 프로젝트는 의존성 없는 정적 사이트이므로 별도 패키지 설치가 필요 없습니다.

## Supabase 연결 상태

새 프로젝트 `검단신도시부자부동산` (서울 리전, ref `ngbjsutgtyorjhroiutz`)을 만들고 이 사이트의 `config.js`에 연결했습니다. `supabase/schema.sql`을 SQL Editor에서 실행했고, 매물·문의·게시글·고객·상담 테이블 5개에 RLS가 켜진 것을 확인했습니다. 공개 매물/게시글 뷰와 사진 저장소 정책도 생성되었습니다. 기존 상권메이트 프로젝트는 변경하지 않았습니다.

관리자 Auth 계정 `prorerty98@naver.com`을 생성했고 `app_metadata.role=admin` 권한을 지정했습니다. 관리자 화면에서 직접 정한 새 비밀번호로 로그인하면 됩니다. 공개 회원 가입은 열지 않았습니다.

관리자 권한은 Supabase SQL Editor에서 아래처럼 지정합니다. 이메일은 본인이 만든 관리자 계정 주소로 바꿔 실행하고, 완료 후 관리자 화면에 다시 로그인하세요.

```sql
update auth.users
set raw_app_meta_data = coalesce(raw_app_meta_data, '{}'::jsonb) || '{"role":"admin"}'::jsonb
where email = 'your-admin-email@example.com';
```

매물 공개 페이지는 `properties_public` 뷰만 조회하고, 게시글은 `blog_posts_public` 뷰만 조회합니다. 고객 이름·전화번호·내부 메모는 관리자 전용 테이블에 남으며 RLS 정책으로 보호합니다. 익명 방문자는 개인정보 이용에 동의한 문의를 제출할 수 있지만 접수 내역을 읽을 수 없습니다. 이미지 저장소는 공개 읽기와 관리자 업로드로 나뉩니다.

## 배포 전 필수 확인

- 제공된 사무실 주소의 행정구역 표기와 중개사무소 등록정보를 실제 사업자 서류와 대조합니다.
- 실제 도메인이 정해지면 `sitemap.xml`에 절대 페이지 URL을 추가하고 `robots.txt`에 sitemap 절대 URL을 입력합니다. canonical 도메인과 SEO 정보도 실제 도메인 확정 후 추가합니다.
- 개인정보 처리방침의 보유기간, 위탁업체, 보호책임자, 시행일을 실제 운영 정책에 맞게 확정합니다.
- 사진은 실제 매물 사진과 게시 권한을 확인한 뒤 업로드합니다. 현재 매물 카드에는 가공된 매물이나 허위 가격을 넣지 않습니다.
- 검단구 주소 표기, 가격/거래 조건, 사진 등은 게시 전에 확인합니다.

## 네이버 블로그 RSS 초안 승인

`https://rss.blog.naver.com/property98.xml` 공식 RSS를 관리자 화면의 **네이버 글 가져오기** 탭에서 새로 확인합니다. 새 글은 매물 또는 정보 글로 선택해 가져올 수 있으며, 모두 비공개 초안으로 저장됩니다. 매물 초안은 거래 유형이 `정보 확인 필요`로 시작하므로 가격·면적·주소·거래 조건을 확인하고 관리자 화면에서 공개로 바꾸기 전까지 홈페이지에 나오지 않습니다. RSS에 없는 정보는 자동으로 채우지 않습니다.

운영 Supabase DB에는 `supabase/migrations/20261022_blog_rss_import.sql`의 추가형 마이그레이션을 적용했습니다. `properties.source_url`, `properties.naver_post_id`, `blog_posts.source_url` 및 중복 방지 인덱스를 추가하며 기존 데이터는 삭제·변경하지 않습니다.

## 현재 범위와 남은 작업

구현됨: 반응형 홈페이지, 실제 전화/카카오톡/네이버 플레이스 링크, 모바일 문의 바, 매물 유형/지역/키워드/가격/면적/층수/주차 필터와 정렬, 매물 상세 보기, 문의 접수 폼, Supabase 공개 매물·게시글 조회, 관리자 인증, 매물 등록/수정/삭제·공개 상태 관리, 사진 업로드, 문의 상태와 내부 메모 편집, 게시글 작성/수정/삭제 및 공개 설정, RLS 초기 스키마. 공개 매물 영역에는 실제 매물과 구분되는 네이버 블로그 현장 사례 카드를 추가했으며, 단독주택 토지 사례를 먼저 보여주고 현재 거래 가능 여부를 별도로 확인하도록 안내합니다. 이전 선양법조타워 별도 사례 페이지는 홈페이지와 검색 사이트맵에서 제거했습니다.

공개 미리보기 운영: Vercel 공개 주소에 배포되어 있으며, 화면에 공개 미리보기 안내가 표시됩니다. 미리보기 중에는 온라인 문의 양식을 비활성화해 방문자 개인정보를 데이터베이스로 보내지 않습니다. 실제 접수를 열기 전 `privacy.html`을 실제 운영 정책에 맞는 개인정보 처리방침으로 확정하고 `config.js`의 `previewOnly`를 `false`로 바꿔야 합니다.

실제 운영 전에 남은 항목: 관리자 로그인 및 매물 등록 흐름 확인, 개인정보 처리방침의 수집 항목·이용 목적·보유 기간·위탁·책임자·시행일 확정, 문의 접수와 이메일 알림의 실전 확인, 검색엔진 색인 설정을 정식 운영 정책에 맞게 조정해야 합니다. 브라우저에는 공개용 publishable key만 설정되어 있으며 secret/service_role 키와 데이터베이스 비밀번호는 넣지 않았습니다. 이메일 알림은 Apps Script 웹앱 배포와 Supabase Vault 트리거 연결까지 완료되어 있습니다. 이전 실행에서 알림 토큰이 노출되었으므로 정식 접수 개방 전 Apps Script의 `WEBHOOK_TOKEN`을 새 값으로 교체하고, Supabase Vault의 `inquiry_notification_url`도 새 URL로 갱신해야 합니다. 이 비밀값은 사이트 코드나 저장소에 넣지 않습니다. 안내는 `google-mail-notifier/SETUP.md`에 있습니다.

아직 미완성: 서버 렌더링 기반 게시글별 검색 URL/구조화 데이터, 매물 상세 개별 URL, 정식 도메인 연결, 개인정보 처리방침 확정, 알림 토큰 교체와 운영 문의 확인. Supabase 스키마 생성과 RLS 활성화는 확인했으며, 관리자 로그인은 관리자가 실제 화면에서 확인해야 합니다.
