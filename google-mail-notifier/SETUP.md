# 새 문의 이메일 알림 운영 안내

문의 양식은 Supabase에 저장하고, 이메일에는 새 문의가 들어왔다는 알림과 관리자 페이지 링크만 보냅니다. 고객 성함·전화번호·상세 요청은 이메일에 포함하지 않습니다.

## 현재 연결 상태

Google Apps Script 웹앱은 배포되어 있고, Supabase Vault에 알림 주소가 저장되어 있으며, `inquiries` 신규 접수 시 실행되는 DB 트리거도 연결되어 있습니다. 알림 메일은 접수 종류·시간·관리자 페이지 링크만 포함합니다. 고객 이름, 전화번호, 상세 요청 내용은 이메일로 보내지 않습니다.

이전 작업 과정에서 기존 알림 토큰이 노출되었을 가능성이 있어 실제 문의 접수를 열기 전에 토큰을 교체해야 합니다. 새 토큰과 토큰이 포함된 웹앱 주소는 사용자가 Google Apps Script와 Supabase 대시보드에 직접 입력하세요. 채팅, GitHub, 홈페이지 코드에는 입력하지 마세요.

## 토큰 교체 절차

1. Google Apps Script에서 프로젝트 `부자부동산 문의 메일 알림`을 열고 **프로젝트 설정 → 스크립트 속성**으로 이동합니다.
2. `WEBHOOK_TOKEN` 값을 새롭고 충분히 긴 임의 문자열로 바꾸고 저장합니다. 이 값은 사용자가 직접 생성·입력하며 다른 곳에 공유하지 않습니다. `NOTIFY_TO` 수신 주소는 그대로 유지합니다.
3. 배포 → 배포 관리에서 현재 웹앱을 수정해 새 버전으로 배포합니다. 기존 배포 URL을 유지합니다.
4. 새 웹앱 URL 뒤에 `?token=`과 방금 저장한 새 토큰을 붙여, Supabase 대시보드 → Database → Vault에서 `inquiry_notification_url` 보관값을 교체합니다. 입력 후 값이 맞는지 확인하고 저장합니다. URL 전체는 외부에 공유하지 않습니다.
5. 두 대시보드에서 저장 완료를 확인한 뒤, 실제 운영 전 최종 개인정보 처리방침을 확정하고 테스트 문의를 제출해 DB 저장과 이메일 수신을 각각 확인합니다. 테스트에는 실제 고객 정보를 쓰지 않습니다.

## 관련 파일

- `Code.gs`: Google Apps Script 웹앱 수신기. 알림 수신 주소는 스크립트 속성에 비공개로 저장합니다.
- `appsscript.json`: Gmail 발송 권한만 요청합니다.
- `../supabase/notify_inquiry_email.sql`: Supabase 문의 등록 후 알림 웹앱을 호출하는 트리거입니다.

## 새 환경에 다시 연결할 때

1. Google 계정으로 [Google Apps Script](https://script.google.com/)에 접속해 새 프로젝트를 만듭니다.
2. 기본 코드 전체를 지우고 이 폴더의 `Code.gs` 내용을 붙여넣습니다. 프로젝트 설정에서 `appsscript.json` 매니페스트 표시를 켠 다음, 파일의 내용을 이 폴더에 있는 매니페스트와 똑같이 저장합니다.
3. 프로젝트 설정의 스크립트 속성에 `NOTIFY_TO` 이름으로 알림을 받을 Gmail 주소와, `WEBHOOK_TOKEN` 이름으로 길고 임의적인 비밀 문자열을 저장합니다. 주소와 비밀 문자열은 홈페이지 코드, GitHub, 일반 문서, 채팅에 넣지 않습니다.
4. **배포 → 새 배포 → 웹 앱**을 선택하고, 실행 사용자는 본인 계정, 액세스 권한은 웹앱 호출이 가능하도록 설정합니다. Google이 요청하는 메일 발송 권한을 직접 검토하고 승인합니다.
5. 배포된 웹앱 주소 뒤에 `?token=`과 3단계의 비밀 문자열을 붙입니다. 이 주소는 공개 문서나 코드에 적지 않습니다.
6. Supabase 대시보드의 Vault에 완성된 웹앱 주소를 `inquiry_notification_url` 이름으로 저장합니다. 주소와 토큰을 SQL 편집기 기록이나 채팅에 남기지 않습니다.
7. Supabase의 SQL Editor에서 `../supabase/notify_inquiry_email.sql`을 실행합니다. 프로젝트에서 `pg_net`과 Vault가 활성화되어 있어야 합니다.
8. 개인정보 처리방침의 수집 항목·이용 목적·보유 기간·문의처를 실제 운영 정책에 맞춰 확정한 뒤, 홈페이지 설정의 미리보기 모드를 해제하고 테스트 문의를 제출합니다. Supabase 관리자 화면에 문의가 저장되고 지정된 Gmail에 알림이 오는지 각각 확인합니다.

## 운영 주의사항

- 배포 버전의 주소가 바뀌면 Vault의 `inquiry_notification_url`도 새 주소로 바꿉니다.
- 비밀 토큰이 노출되면 위 절차에 따라 Apps Script 속성 값과 Vault 주소를 함께 교체합니다.
- 폼 접수는 열렸지만 이메일 전송은 실패할 수 있으므로, 첫 운영 테스트에서 데이터베이스와 이메일을 각각 확인합니다.
- 현재 공개 홈페이지는 의도적으로 미리보기 상태입니다. 위 연결과 개인정보 처리방침 확정 전에는 온라인 접수를 열지 않습니다.
